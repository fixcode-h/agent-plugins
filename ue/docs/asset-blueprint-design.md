# UE 插件扩充设计：资源与蓝图读写

2026-11-10 · 设计稿原文，实现进度和已定的问题见文末「实现状态」

## 结论与目标

现在的 UE 插件是一个「运行时调试 + DataTable 编辑」工具，离「Agent 直接读写各类资源和蓝图」还差三块：**蓝图图表完全读不到**、**资源只能改属性不能建删改名**、**写入没有事务和校验**。建议分五期补齐，先做只读（风险低、马上有用），再做写入，蓝图写放在事务和编译回读都就绪之后。

目标按能力分四层，每层都要求 Agent 不看界面就能完成：

1. **看得全**：任意资源能拿到结构化的完整内容，包括蓝图的变量、组件、函数和每张图的节点连线。
2. **找得到**：按类型、路径、引用关系、内容搜索资源和蓝图节点。
3. **改得动**：新建、复制、改名、移动、删除资源；改属性、改表、改蓝图图表。
4. **改得稳**：每次写入可演练、可撤销、有编译和校验结果回读，保存前请用户确认。

本文依据 `fixcode-h/agent-plugins` 的 `main`（提交 `0b22e99`，UE 插件 0.1.5，桥接 1.1.1）。只做设计，不含代码改动。

## 现状：已有的能力

插件已经有 13 个 `ue_*` 工具、34 个桥接操作，强项在运行时；资源侧只有「按名字搜、反射读写属性、DataTable 行编辑、保存」。

| 领域       | 已有能力                                                                                            | 入口                                                                                       |
| ---------- | --------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| 进程与目标 | 列出编辑器、PIE、游戏、专用服务器进程和各自的世界；启动编辑器、开关 PIE、编译、Live Coding          | `ue_status`、`ue_editor`                                                                   |
| 运行时调试 | 控制台命令和变量、GM、按前缀找 Actor / 组件 / UObject、反射读写属性、调函数、UMG 控件树、日志、截图 | `ue_console`、`ue_gm`、`ue_find`、`ue_get`、`ue_set`、`ue_call`、`ue_log`、`ue_screenshot` |
| UnLua      | 搜绑定了 Lua 的对象、读改实例表字段、执行 Lua（每次确认）                                           | `ue_find kind=lua`、`ue_get` / `ue_set` 的 `lua`、`ue_lua`                                 |

| 保存       | 列出改了没存的包、保存（P4 先签出）、放弃改动、在编辑器里打开                                       | `ue_asset dirty / save / revert / open`                                                    |
| 离线       | 编辑器没开时起后台编辑器（`-run=AgentPanel`）读写资源，闲置自动退出                                 | 自动                                                                                       |
| 安全       | 运行时和资源各有「只读 / 询问 / 允许」权限；危险命令确认；操作记录；运行时修改可 `ue_undo`          | `ops.ts`                                                                                   |

三个和后续设计直接相关的实现细节：

- **蓝图被换成了类默认对象**。`FindObjectByPath` 遇到 `UBlueprint` 直接返回 `GeneratedClass` 的 CDO，所以蓝图资源本身（图表、变量定义、组件树）现在没有任何路径能到。
- **资源写入没进编辑器的事务**。改属性时调了 `Modify()` 和 `PostEditChangeProperty`，但外面没有 `FScopedTransaction`，编辑器的撤销栈里没有这一步；`ue_undo` 也只管运行时，资源只能整包「放弃改动」。
- **C++ 还没在真实引擎上编译过**。README 写明 5.4 / 5.5 / 5.6 都没实测，面板侧只用 `fake-bridge.mjs` 做冒烟。扩充之前这一步必须先补。

## 缺口：还缺什么

缺口有 9 项，前 4 项直接挡住「读写资源和蓝图」这个目标，后 5 项决定写入敢不敢交给 Agent。

| #   | 缺口                       | 现在的表现                                                                                                              | 归到哪一期     |
| --- | -------------------------- | ----------------------------------------------------------------------------------------------------------------------- | -------------- |
| 1   | 蓝图图表读不到             | 只能读类默认值；事件图、函数、宏、变量定义、组件树、接口、编译状态都拿不到                                              | 一期           |
| 2   | 蓝图写不了                 | 不能加变量、函数、组件、节点、连线，不能编译                                                                            | 三期           |
| 3   | 资源不能建、删、改名       | 没有新建、复制、改名、移动、删除、导入；Agent 只能改已有资源                                                            | 二期           |
| 4   | 资源内容看不全             | 只能一个属性一个属性地读，对象引用只给路径；没有「整份导出」，实例化子对象（如 DataAsset 里的内嵌对象数组）不能新增元素 | 一期读、二期写 |
| 5   | 找资源手段少               | 只按名字前缀和类；没有引用关系（谁用了它、它用了谁）、没有按标签或内容搜、没有蓝图内搜索                                | 一期           |
| 6   | 写入没有事务               | 一次改多处不能整体成功或整体回滚；编辑器里按 Ctrl+Z 撤不掉；没有演练                                                    | 二期           |
| 7   | 写完没有校验               | 不编译蓝图、不跑数据校验、不回读编译错误，Agent 不知道自己改坏没有                                                      | 二期、三期     |
| 8   | 类型专用操作只有 DataTable | 曲线、字符串表、材质实例参数、自定义结构和枚举、UMG 控件树、关卡里的 Actor、动画通知、行为树都只能当普通属性碰运气      | 二期起逐类加   |
| 9   | 没在真实引擎上验证         | 桥接 C++ 未编译实测；后台编辑器的 HTTP 服务能否被 commandlet 循环驱动也待确认                                           | 零期           |

另有一个结构性问题：`ue_asset` 的 `action` 已有 11 个取值，说明文字接近上限。能力再加几倍，不能继续往一个工具的枚举里塞，需要「少量工具 + 可查询的动作表」（见总体设计）。

## 总体设计

沿用现有的四层结构不变，新能力集中加在两处：Agent 工具层加 2 个工具并扩充 `ue_asset`，桥接的编辑器模块加「事务、资源通用层、类型适配器、蓝图图表」四块。运行时模块不动。

（分层自上而下：Agent 工具 → 面板插件服务端（权限、确认、操作记录、P4）→ 桥接协议 → 桥接编辑器模块（事务、资源通用层、类型适配器、蓝图图表）→ 引擎。）

读写请求自上而下经过每一层；权限、确认、操作记录和 P4 仍由面板插件服务端统一把关，桥接只管执行。

### 工具面：少量工具加动作表

| 工具           | 变化       | 负责                                                                                                                                          |
| -------------- | ---------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| `ue_find`      | 扩充       | `kind=asset` 加标签、引用关系、内容搜索；新增 `kind=node` 在蓝图里搜节点                                                                      |
| `ue_asset`     | 扩充       | 资源的通用读写：`describe`、`export`、`refs`、`create`、`duplicate`、`rename`、`move`、`delete`、`import`、`validate`，以及各类型适配器的动作 |
| `ue_blueprint` | 新增       | 蓝图专用：`outline`、`graph`、`node_search`、`edit`、`compile`                                                                                |
| `ue_python`    | 新增，兜底 | 在编辑器里执行 Python（需项目启用 Python 插件）；和 `ue_lua` 一样每次都请用户确认                                                             |
| `ue_undo`      | 扩充       | 能撤回本对话做的、还没保存的资源修改                                                                                                          |

`ue_asset` 的动作不再全写进工具说明。工具说明只列通用动作，各类型的专用动作用 `ue_asset action=help class=<类名>` 现查：返回这个类型支持哪些动作、每个动作的参数。这和面板 ADR 0011「两个固定工具 + 动作表」是同一个思路，加类型只加适配器，不改工具定义。

### 桥接：四个新模块

- **事务与批量**（`asset.batch`）。一次请求带一组操作，包在一个 `FScopedTransaction` 里；任一步失败整体取消。支持 `dryRun`：照常执行、收集结果和校验信息，然后取消事务，不留改动。
- **资源通用层**。新建（按类或工厂）、复制、改名和移动（修正重定向器）、删除（先查引用）、导入、引用查询、整份导出。和具体类型无关。
- **类型适配器**。每种资源一个适配器，登记「类 → 摘要怎么出、有哪些专用动作」。DataTable 现有代码改造成第一个适配器，后面逐类加。没有适配器的类型仍可用通用层的属性读写。
- **蓝图图表**。单独一个文件组，依赖 `BlueprintGraph`、`KismetCompiler`、`Kismet` 模块，只在编辑器模块里。

编辑器模块现在只有一个 366 行的文件，扩充后按上面四块拆目录，避免单文件膨胀。

### 地址规则

蓝图要能同时指到「蓝图资源本身」和「类默认值」。约定：`/Game/BP_Hero` 在 `ue_get` / `ue_set` 里仍是类默认值（不破坏现有行为），在 `ue_blueprint` 和 `ue_asset` 里是蓝图资源本身。桥接里 `FindObjectByPath` 加一个参数控制要不要换成 CDO。

图里的节点用节点 GUID 的前 8 位做 id，引脚用引脚名；同一张图里 id 撞了就加长。Agent 新建的节点在同一批操作里用自己起的临时名互相引用。

## 资源读写

资源读写分两层：通用层对任何资源都能用，类型适配器在通用层够不着的地方补专用动作。

### 通用层的动作

| 动作              | 读 / 写 | 做什么                                                                                                                   |
| ----------------- | ------- | ------------------------------------------------------------------------------------------------------------------------ |
| `describe`        | 读      | 一份摘要：类、父类、磁盘文件和大小、资源注册表标签、是否已加载和已改动、子对象大纲、依赖和被引用的数量                   |
| `export`          | 读      | 整份导出成 JSON：属性按反射展开，实例化子对象就地展开，其他对象引用只给路径；按 `depth` 限深、按 `cursor` 分页，防止超长 |
| `refs`            | 读      | 依赖（它用了谁）和被引用（谁用了它），可限硬引用或软引用、可递归几层                                                     |
| `create`          | 写      | 按类名或工厂新建资源，可指定父类（蓝图、DataAsset 子类）、行结构（DataTable）等                                          |
| `duplicate`       | 写      | 复制到新路径                                                                                                             |
| `rename` / `move` | 写      | 改名或移动，随后修正重定向器；P4 项目走 `p4 move`                                                                        |
| `delete`          | 写      | 先查被引用，有引用时默认拒绝并列出引用方；每次都请用户确认                                                               |
| `import`          | 写      | 把磁盘上的文件（贴图、FBX、CSV、JSON）导入成资源，或对已有资源重新导入                                                   |
| `validate`        | 读      | 跑编辑器的数据校验，返回每个资源的错误和警告                                                                             |

属性的读写继续用 `ue_get` / `ue_set`，补两点：数组和 Map 支持插入、删除元素（现在只能整体赋值）；属性类型是实例化子对象时，可以按类名新建一个子对象放进去。

| 资源类型               | 专用读                                               | 专用写                                                                        | 期                   |
| ---------------------- | ---------------------------------------------------- | ----------------------------------------------------------------------------- | -------------------- |

| CurveTable、曲线       | 读键和插值方式                                       | 增删改键                                                                      | 二期                 |
| StringTable            | 读条目                                               | 增删改条目                                                                    | 二期                 |
| DataAsset              | 通用层已够                                           | 通用层加子对象新建                                                            | 二期                 |
| 自定义结构、自定义枚举 | 读成员和默认值                                       | 增删改成员（会影响引用它的表和蓝图，结果里列出受影响资源）                    | 二期                 |
| 材质实例               | 读参数覆盖和父材质链                                 | 改标量、向量、贴图参数，换父材质                                              | 二期                 |
| 蓝图                   | 见下一节                                             | 见下一节                                                                      | 一期读、三期写       |

| 材质                   | 表达式节点和连线                                     | 增删节点、连线、重新编译                                                      | 四期                 |
| 动画（序列、蒙太奇）   | 长度、曲线、通知、分段                               | 增删改通知和分段                                                              | 四期                 |
| 行为树、黑板           | 树结构、黑板键                                       | 增删改节点和键                                                                | 四期                 |
| 贴图、网格、音频       | 尺寸、面数、导入设置等元数据                         | 改导入设置、重新导入；不改像素和几何                                          | 四期                 |

适配器的顺序按「纯数据、改错容易发现」优先。带图表的类型（材质、行为树）都放在蓝图写入稳定之后，复用同一套「节点、引脚、连线」的读写表示。

### JSON 导出与导入

导出 JSON 对所有资源都可行，是查看的主格式；从 JSON 导入生成 uasset 对纯数据资源可行，对蓝图图表只能做到「按 JSON 重建」，做不到无损往返。

| 方向                 | 纯数据资源（DataTable、DataAsset、曲线、字符串表、材质实例、自定义结构）                 | 蓝图                                                                                                 |
| -------------------- | ---------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| uasset 导出 JSON     | 可行，一期做。`export` 的结果可以直接返回，也可以写成文件放到 `Saved/AgentPanel/export/` | 可行，一期做。大纲加每张图的节点连线，另附伪代码；查看蓝图主要靠这个                                 |
| JSON 导入生成 uasset | 可行，二期做。按类新建资源再逐个属性写入；DataTable 引擎本身就支持 JSON 整表导入         | 受限，三期之后做。不是把 JSON 反序列化成图，而是把 JSON 翻译成操作列表重放：逐个生成节点、连线、编译 |

蓝图 JSON 往返的三个限制：

- **节点不能凭数据还原。** 蓝图节点的引脚是节点按引用的函数、变量、类现场生成的，JSON 里只能记「这是对哪个函数的调用」，导入时要让引擎重新生成节点。引用的东西不存在或签名变了，这个节点就建不出来。
- **只覆盖能生成的节点。** 能重建的范围等于 `node_search` 能放出来的节点。时间轴、动画状态机、部分插件自带的特殊节点第一版不支持，导入时逐条报出来，不悄悄跳过。
- **不是原样还原。** 重建出的蓝图节点 id、位置、内部版本信息和原来不同，逻辑等价但文件不同。所以它适合「新建蓝图」「新增一个函数」「把一段逻辑搬到另一个蓝图」，不适合拿来覆盖一个已有的复杂蓝图；改已有蓝图仍走上一节的操作列表。

另外，JSON 里只有属性和引用路径，不含贴图像素、网格几何、音频这类二进制内容。导入时引用的资源必须已经在项目里，缺的在演练结果里列出。

导出文件带一个格式版本号和导出时的引擎版本，导入时检查；格式定下来后，导出、对话里的查看弹窗、导入、后面的资源差异对比都用同一份。

推荐的组合是「伪代码用来看、操作列表用来改、JSON 用来存档和搬运」，不把 JSON 互转当成唯一通道：

| 方案                         | 看蓝图                                | 改蓝图                                 | 结论                           |
| ---------------------------- | ------------------------------------- | -------------------------------------- | ------------------------------ |
| JSON 互转                    | 完整但冗长，节点多时人和 Agent 都难读 | 改一处也要整份导入重建，有上面三个限制 | 做，用于存档、对比、新建和搬运 |
| 伪代码                       | 最好读，沿执行线一行一句              | 不直接用来写（后续可以做伪代码写入）   | 做，作为查看蓝图的默认方式     |
| 操作列表                     | 不适用                                | 只发改动，在事务里执行，改完就编译     | 做，作为修改已有蓝图的主路径   |
| 引擎节点文本（复制粘贴格式） | 几乎不可读                            | 无损，但只能整段搬，很难手写           | 只作备用通道                   |
| 编辑器 Python                | 需要自己写脚本                        | 能改属性和资源，对蓝图节点的支持很少   | 只作兜底                       |

## 蓝图读写

蓝图按「三级读取、操作列表写入、编译回读」设计：读的时候由粗到细省上下文，写的时候只发改动不发整张图，每次写完立刻编译并把错误带节点 id 返回。

### 读：三级

| 级别     | 动作                          | 返回                                                                                                                                                       |
| -------- | ----------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 大纲     | `ue_blueprint action=outline` | 父类、实现的接口、变量（类型、默认值、是否同步、分类）、组件树、事件图和函数和宏的列表（各自的节点数、入参出参）、事件分发器、时间轴、编译状态和上次的错误 |
| 一张图   | `action=graph graph=<名字>`   | 这张图的节点和连线，默认给伪代码，`format=json` 给完整结构                                                                                                 |
| 一个节点 | `action=graph node=<id>`      | 这个节点的全部引脚、默认值、连到谁、注释、位置                                                                                                             |

一张图有两种表示，各有用途：

- **伪代码**（默认，用来读懂逻辑）。从每个事件或函数入口沿执行线往下走，把节点写成一行一句，数据引脚内联成表达式，每行末尾带节点 id。一张 80 个节点的图大约几十行，比 JSON 省一个数量级的上下文。
- **JSON**（用来准备修改）。每个节点给 id、种类、标题、引脚列表；每个引脚给名字、方向、类型、默认值、连到的 `节点id.引脚名`。大图按 `offset` / `limit` 分页，或用 `around=<节点id>` 只取某个节点周围几跳。

伪代码的样子（示意）：

```
Event BeginPlay                                  #a1b2c3d4
  HP = MaxHP                                     #0f3e77a1
  if IsValid(GetOwner()):                        #9c0d1e2f
    Widget = CreateWidget(WBP_HUD, GetOwner())   #5a6b7c8d
    Widget.AddToViewport()                       #1e2f3a4b
```

纯数据节点没有执行线，挂在用到它的那一行里；没连到任何执行线的孤立节点单独列在末尾，避免漏看。

另外加 `ue_find kind=node`：跨蓝图搜「调用了某函数、读写了某变量、用了某个类」的节点，底层用编辑器的 Find in Blueprints 索引。

### 写：操作列表

`ue_blueprint action=edit` 接受一个操作数组，整批在一个事务里执行。不提供「整张图替换」，原因是整图替换会丢掉 Agent 没读到的部分，而且一处写错全图报废。

| 类别   | 操作                                                                                                                           |
| ------ | ------------------------------------------------------------------------------------------------------------------------------ |
| 成员   | 增删改变量（类型、默认值、同步、分类、可见性）；增删函数、宏、自定义事件、事件分发器；改函数的入参出参和修饰（纯函数、可重写） |
| 类设置 | 换父类、加减接口、改类默认值                                                                                                   |
| 组件   | 加组件、改层级、删除、改组件模板的属性                                                                                         |
| 节点   | `add_node`、`remove_node`、`set_pin`（改引脚默认值）、`connect`、`disconnect`、`move`、`comment`（加注释框）                   |

`add_node` 不让 Agent 直接写 K2Node 的类名。先用 `action=node_search` 查：给关键字和上下文（在哪张图、从哪个引脚拖出来），返回和编辑器右键菜单一致的候选项，每项带一个 `spawner` 键；`add_node` 传这个键。这样能放的节点范围、参数和编辑器里完全一致，函数调用、变量读写、分支、循环、类型转换、宏、事件都走同一条路。

连线走引脚所在图的规则检查（和手动拖线同一个判断），类型不匹配时返回编辑器给的原因；需要自动插入转换节点的，按编辑器行为插入并在结果里说明。

新节点的位置由桥接自动排：接在执行线后面的往右放，数据节点放在使用者左下方。Agent 不需要管坐标，也可以用 `move` 指定。

### 编译回读

`edit` 执行完默认立刻编译，返回：

- 每个操作的结果，新建节点的 id；
- 编译状态，以及每条错误和警告对应的图名和节点 id；
- 这次改动影响到的其他蓝图（子类、调用方），它们是否仍能编译。

推荐的工作循环：

1. `outline` 看整体，`graph` 读要改的图。
2. `node_search` 查要放的节点。
3. `edit` 带 `dryRun=true` 演练，看操作结果和编译错误。
4. 没问题后正式 `edit`；有编译错误就按节点 id 继续修。
5. `ue_asset save` 保存，按权限请用户确认。

### 边界

- 一期到三期只支持普通蓝图（Actor、组件、对象、函数库、接口）。动画蓝图的状态机和控件蓝图的控件树放四期。
- 蓝图写入只在有编辑器模块的进程里做。已打开的编辑器里如果这个蓝图的编辑器窗口开着，改完通知它刷新，不关窗口。
- 批量搬运一段节点时，保留「引擎的节点文本格式」作为备用通道（等同于编辑器里复制粘贴），不作为主路径，因为这种文本 Agent 很难手写正确。

## 安全与可靠性

写入能力放大之后，靠五道关保证 Agent 改不坏项目：权限、事务、演练、校验、保存确认。前四道都发生在内存里，只有保存才落盘。

| 关   | 规则                                                                                                                                                                                |
| ---- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 权限 | 现有的资源权限（只读 / 询问 / 允许）继续管「改内容」。新增一档「结构性操作」管新建、改名、移动、删除，默认询问。删除不管权限设成什么，每次都确认。`ue_python` 同 `ue_lua`，每次确认 |
| 事务 | 所有资源写入包进编辑器事务。编辑器里能按 Ctrl+Z 撤掉；`ue_undo` 对还没保存的资源修改调用同一个撤销；批量操作任一步失败整体取消                                                      |
| 演练 | `dryRun=true` 真实执行后取消事务，返回「会改什么、编译和校验结果是什么」。蓝图写入和结构性操作建议 Agent 先演练                                                                     |
| 校验 | 蓝图写完编译；其他资源写完跑数据校验；改了结构体或枚举时，列出引用它的资源并重新检查                                                                                                |
| 保存 | 沿用现有流程：列出脏包，按权限请用户确认，P4 项目先签出。新增：新建的文件 `p4 add`，改名走 `p4 move`，删除走 `p4 delete`，都进默认变更列表、不提交                                  |

其他可靠性规则：

- **谁来写**。编辑器开着时，资源写入一律发给它，不发给后台编辑器；两个进程同时改同一个包会互相覆盖。编辑器启动时，后台编辑器若有未保存的改动先报告给用户，不自动保存也不自动丢弃。
- **长操作变作业**。导入大文件、编译有很多子类的蓝图、整目录校验可能超过现在 30 秒的请求时限。这类操作返回作业 id，结果用同一个 id 再取，复用现有编译作业的做法。
- **结果限长**。导出、图表、引用查询都按现有约定先给摘要再给细节，超长的给游标分页。
- **错误原样返回**。编译错误、校验错误、引擎拒绝的原因不改写、不自动重试，和面板「Agent 执行出的错误一律显示给用户」的规则一致。
- **引擎版本差异**。5.4 到 5.6 之间蓝图和资源工具的接口有改名，集中包在一个兼容头文件里，不散落在各操作里。
- **操作记录**。资源写入记进现有操作记录，摘要里写清「哪个资源的什么」，蓝图写入记操作列表和编译结果。

## 与 agent-panel 的衔接

Agent 工具这部分全部在现有插件接口 2 之内完成，不需要面板加接口；面板侧要配合的是编译规则和 P4 规则对齐。对话里的 uasset 查看弹窗共用同一套读取能力，它从对话里打开的入口是否要面板加扩展点，由那条线程确定。

- **对话里的 uasset 查看弹窗**。用户已另提需求：在 Agent 对话里点开 uasset 文件弹窗看属性，先支持 DataTable 和 DataAsset，读取能力放在 UE 插件里。它和本设计的一期是同一件事的两个出口：弹窗和 Agent 工具都调通用层的 `describe`、`export` 和 DataTable 适配器。约定弹窗不自己写一套读取代码，只做展示；以后每加一个类型适配器，弹窗就多支持一种资源，蓝图大纲和图表的只读视图也按这个方式接进弹窗。
- **技能和角色**。现有 `ue-runtime-debug` 技能只讲运行时排查。新增 `ue-asset-authoring` 技能，讲读写资源和蓝图的工作循环（先读、演练、写、看编译、保存）；新增「UE 资源」角色挂这个技能。「UE 调试」角色不变。
- **权限界面**。UE 页「桥接与权限」加「结构性操作」一档，以及 `ue_python` 的开关（默认关）。
- **编译规则**。只改资源和蓝图不触发 C++ 编译，蓝图编译在桥接里完成，符合面板「改了什么才编什么」的规则。桥接插件自己升级时要重编项目，这一步仍归父对话发起并按编译目录排队（面板 ADR 0004）。
- **P4 变更列表**。面板有按 C++ / 表格 / Lua / 其他拆变更列表的工具。Agent 通过插件改出的 uasset 进默认变更列表后，由那套工具按类型归类，插件不另做一套。
- **子对话**。多个子对话同时改同一个资源会在编辑器里互相覆盖。一期先由桥接对「正在被另一个对话的事务修改的包」报错；是否需要像编译那样按资源占位排队，放到待确认的问题里。
- **界面文案**。新增的工具显示名、权限项、弹窗文案照插件仓库约定写 `t('中文原文')` 并补 `locales/en.json`；发给 Agent 的工具说明不翻译。

## 分期计划

分五期，每期结束都能独立发版；顺序按「先验证、先只读、写入从纯数据到图表」排。

1. **零期：打底。** 在真实引擎 5.4 / 5.5 / 5.6 上把现有桥接编译通过并实测，确认 README 列的四个待验证点（清空日志、后台编辑器的 HTTP 服务、PIE 多客户端世界 id、UnLua 接口选择）。编辑器模块按新结构拆文件，DataTable 改成第一个适配器，行为不变。
2. **一期：读全。** 通用层的 `describe`、`export`、`refs`，`ue_find` 加标签和引用条件；蓝图的 `outline`、`graph`（伪代码和 JSON）、`ue_find kind=node`。同期交付对话里的 uasset 查看弹窗（DataTable、DataAsset）。全部只读，不涉及权限变化。
3. **二期：资源写入。** 事务、批量、演练；新建、复制、改名、移动、删除、导入；「结构性操作」权限和 P4 的添加、移动、删除；`ue_undo` 覆盖资源；数据校验；曲线、字符串表、自定义结构和枚举、材质实例的适配器。
4. **三期：蓝图写入。** 先做成员、类设置、组件（不碰图表，风险小），再做 `node_search` 和节点连线编辑，最后接编译回读和受影响蓝图检查。新增 `ue-asset-authoring` 技能和「UE 资源」角色。
5. **四期：类型扩展。** 控件蓝图的控件树、关卡 Actor、材质图表、动画通知、行为树、贴图和网格的导入设置；`ue_python` 兜底。这一期各项互相独立，按项目实际需要挑着做。

每一期的验收都要在真实项目上跑，不只靠 `fake-bridge.mjs`：`fake-bridge` 模拟不了蓝图编译和事务回滚，冒烟测试只能覆盖面板侧的参数、权限和确认流程。

## 后续扩展方向

五期之外还有六个方向值得留口子，现在不做，但设计上不要堵死。

- **资源差异。** 对比资源的内存版本和磁盘版本、或两个版本库修订，输出属性级和节点级差异。Agent 改完可以自查，用户确认保存时也能看到改了什么，比只列包名有用得多。
- **按意图生成蓝图。** 在操作列表之上加一层「伪代码写入」：Agent 提交一段和读取格式相同的伪代码，桥接翻译成操作列表。读写同一种表示，写起来更快；前提是三期的操作列表足够稳定。
- **批量重构。** 跨资源的改名和替换，例如把所有蓝图里对某个函数的调用换成另一个，或批量改一批 DataAsset 的同一个字段。建立在 `refs`、`ue_find kind=node` 和批量事务之上。
- **项目自定义适配器。** 把适配器登记接口公开给项目模块，项目可以给自己的资源类型（技能配置、任务图、对话树）写适配器，和现有 `UAgentPanelGMLibrary`、`SetStateProvider` 的扩展方式一致。
- **无编辑器读取。** 后台编辑器首次启动要 30 到 60 秒、占 2 到 6 GB 内存。只读场景可以考虑不起引擎直接解析 uasset 文件头和属性，用于快速预览；只能覆盖简单类型，蓝图图表仍需引擎。
- **自动化验证。** 写完蓝图后自动开 PIE 跑一段、截图、看日志，用现有运行时工具验证行为，形成「改资源、跑、看结果」的闭环。

### 要在真实引擎上验证的

除了 README「状态」一节原有的四点，这次新增：

- 编辑器模块新加了 `AssetTools`、`BlueprintGraph` 两个模块依赖，要完整编译，Live Coding 带不上。
- 事务：`dryRun` 和失败回滚靠撤销事务。要确认撤销后蓝图重新编译能回到原样，以及后台编辑器（commandlet）里有没有可用的撤销缓冲。没有时桥接会明确报「没法演练」。
- 节点候选（`FBlueprintActionDatabase`）第一次查询要建全量索引，可能要几秒到十几秒；`spawner` 键在编辑器重启后是否稳定。
- 伪代码在大图、带宏和循环的图上的可读性；`goto` 的汇合点是否够清楚。
- 改名后的重定向器和脏包列表；P4 项目里删除只读文件的顺序。
- 5.6 的图表坐标接口（`AgentPanelCompat.h` 里只有这一处版本判断，实际编译可能还会冒出别的）。
